# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Общие правила курса — в `../CLAUDE.md`; здесь только то, что касается этого проекта.

## Что это

Учебный консольный скрипт заметок: добавить строку, показать все, изменить и
удалить по номеру. В будущем может вырасти в небольшой сервис.

## Установка, запуск, проверка

Команды — в `README.md`; здесь не дублировать.

Ставить **только с `-e`**: путь к данным считается от
`src/notes/database.py` (`parents[2]` — корень проекта). При обычной
установке пакет копируется в `.venv`, и путь укажет внутрь окружения.

## Отступления от раскладки курса

Пакет `src/notes/` по раскладке `../CLAUDE.md`; имена модулей — по заданию
(`main.py`, `database.py`, `utils.py`). Отличия:

- **Сборка частей — в `main.py`, а не в `__main__.py`**: точку входа задание
  называет `main.py`. Место сборки по-прежнему одно; `__main__.py` только
  вызывает `main()` ради `python -m notes`.
- **Нет `ports.py`**: протокол нужен для того, что ядру требуется от внешнего
  мира, а ядро (`utils.py`) к хранилищу не обращается — читает и пишет
  `main.py`. Завести, когда правило начнёт вызывать хранилище.
- **Docker не нужен** — проект учебный, в контейнере его не запускают;
  `docker/` не заводить.

## Устройство `src/notes/`

- **`utils.py` — правила**: `add_note`, `delete_note`, `edit_note`,
  `format_notes`, `check_number`. Чистые функции: принимают список и
  возвращают новый, ничего не импортируют, не трогают ни файл, ни консоль.
  Ошибка ввода — `ValueError` с текстом для человека. Номер заметки для
  человека начинается с 1.
- **`database.py` — хранение**: `NOTES_FILE`, `load_notes`, `save_notes`,
  `StorageError`.
- **`main.py` — консоль и сборка**: `main(path)`, `MENU`, `parse_number`;
  единственное место с `input`/`print`. Модули подключаются как
  `from notes import database, utils` и вызываются с префиксом модуля.

Направление зависимостей: `main → database, utils`; `utils` и `database`
друг о друге не знают. Правила не переносить в обработку ввода или в
функции хранения.

## Хранение в `data/notes.json`

- `NOTES_FILE` — `data/notes.json` в корне проекта; `data/` целиком в
  `.gitignore`, создаётся первой записью. Формат — JSON-список строк,
  `ensure_ascii=False`. Нет файла — пустой список.
- Запись целиком после каждого изменения: во временный `notes.json.tmp`, затем
  `os.replace` — прерванная запись не портит прежний файл.
- Испорченный или чужой файл при запуске: выход с кодом 1 и сообщением, файл
  **не перезаписывается** — иначе заметки пропадут. Это поведение не менять.
- В `main()` новый список присваивается `notes` только после успешного
  `save_notes`: при `OSError` изменение отменяется, память не расходится с
  файлом.
- `data/` — личные данные: не читать и не печатать содержимое.

## Тесты

По файлу на модуль: `test_utils.py`, `test_database.py`, `test_main.py`;
импортируют установленный пакет. Меню проверяется через
`main(tmp_path / "notes.json")`; `feed()` подменяет `input` и возвращает
заданные вопросы — по ним видно, о чём программа спрашивала. Сбой записи
имитируется подменой `notes.database.save_notes`. Боевой `data/` тесты не
трогают: только `tmp_path`.
